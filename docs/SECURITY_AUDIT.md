# Antigas security audit

**Snapshot:** 2026-09-29
**Branch:** `security-hardening`
**Method:** source/configuration review, repository/history secret-pattern scan, static parsing, unit tests, and local .NET builds. No production connection, deployment, destructive probe, or public attack simulation was performed.

**Finding totals:** 0 confirmed P0; 0 confirmed unconditional P1; 1 conditional P1; 4 open P2; 1 open P3. Fixed items are listed separately and are not counted as open findings. These are findings from source review, not a claim that the live server has been penetration-tested.

## Inventory and architecture map

The tracked repository contains 1,691 files: 77 C++ sources, 85 C++ headers, one C source, 748 Lua scripts, 246 XML files, 337 NPC files, 39 `.ndb` data files, 35 JSON files, 3 SQL files, 24 Python files, 3 Shell scripts, 6 PHP files, 7 C# sources, CMake files, and client/server data assets. No Makefile, Dockerfile, submodule, or GitHub Actions workflow existed at the start of this audit. `config.lua` is intentionally ignored.

## Findings

| ID / severity / file / function | Finding, condition and impact | Safe reproduction, correction, test and residual risk |
|---|---|---|
| NET-01 · P1 conditional · `src/server.cpp:114-121`, `src/connection.cpp:31-37,144-151` · `ServicePort::accept`, `ConnectionManager::createConnection` | The listener allocates/tracks a connection for each pending TCP accept without a global/per-IP cap. Packet throttling is per socket; `maxPlayers` is reached later. Each socket carries fixed buffers/timers and outgoing messages queue in a list. If the game port is publicly reachable, slow/unauthenticated clients can exhaust memory, descriptors, timers or async work. | Verify listeners/firewall first; measure idle sockets, NAT peaks and output backlog in isolated staging. Then set measured global/per-IP limits and bounded output queues. No limit was applied because safe values require real traffic data. No DoS test was run. |
| CRASH-01 · P2 · `src/tasks.cpp:27-55` · `Dispatcher::threadMain` | A queued task is called with no exception boundary. An exception escaping a `std::thread` entry terminates the process. No client-controlled task was proven to throw; catching and continuing could leave partially mutated world state. | Add a controlled throwing-task regression in a native test build and review task invariants before deciding fail-fast versus recoverable handling. No change/test here; restart policy is external. |
| SCHED-01 · P2 · `src/scheduler.cpp:24-55,101-118`, `src/luascript.cpp:3470-3500` · scheduler `threadMain`, `stopEvent` | `stopEvent` removes the event ID and Lua references, but a cancelled `SchedulerTask` stays in the priority queue until its deadline, when the scheduler discards it. Repeated long-delay event creation/cancellation can retain queue nodes and closures until expiry. Client reachability depends on specific scripts; no exploit path was established. | Reproduce only with a bounded staging test that schedules/cancels known-long timers and samples queue/memory. Consider indexed deletion or periodic compaction only after measuring cost. No change/test here. |
| AUTH-01 · P2 · `src/iologindata.cpp:65,99`, `deploy/site-public/index.php`, `deploy/site-public/account.php`, `config.example.lua:61` · login/registration/password update | Unsalted SHA-1 hashes allow fast offline password guessing after DB disclosure. The legacy game protocol expects its existing credential representation, so changing it directly could lock out players or break clients. | Plan a versioned migration/rehash-on-login compatible with the current protocol, plus reset/rate-limit controls. No hash migration or password test was run. |
| DB-01 · P2 · `src/database.cpp:139-175` and Lua dynamic queries · `Database::executeQuery`, `escapeString` | C++ assembles SQL strings and escapes text against the current MySQL connection; no prepared-statement API or explicit client charset setup was found. Reviewed user-supplied strings generally use `db.escapeString`; no exploitable SQL injection was confirmed. Manual escaping remains dependent on connection charset and correct use at every call site. | Use parameterized statements for new/high-risk calls and explicitly set/verify charset; review each dynamic query and DB privileges before broad migration. Static query review only; no injection test against a real or staging DB. |
| LUA-01 · P3 · `data/lib/lamp_states.lua:54`, `data/lib/core/analyzersLib.lua:174` · `unserialize` | `loadstring` evaluates serialized text as Lua code. The lamp state file is server-local and generated from server state; no client-controlled flow was found. A write compromise of the data tree could execute code on startup. | Replace with a data-only format/parser when compatible; restrict writable paths. No Lua runtime/linter available, and no hostile file was executed. |
| PERF-01 · Fixed in this branch · `data/lib/core/game.lua:129-140` · Lua debug line hook | The hook initialized/reset its timestamp with `os.time()` seconds but compared it with `os.mtime()` milliseconds. The interval check was therefore inconsistent and ran its timing path on effectively every Lua line, adding avoidable overhead and breaking the one-second counter window. | Both endpoints now use millisecond time and compare against 1,000 ms. | NET-02 · Fixed in this branch · `src/server.cpp:125-154` · `ServicePort::onAccept` | A failed/cancelled accept, or a shutdown race where services were empty, could leave the pre-registered connection retained by `ConnectionManager`. `WEB-01` is an external review gap rather than a confirmed vulnerability: private `security.php`, `pix.php`, webhook/payment code, production TLS/headers, DB grants and deployed service configuration are absent. The visible account/order PHP uses PDO prepared statements, but that does not establish the safety of those private paths.

## Positive controls observed

- Packet length is bounded before body reads (`src/connection.cpp:157`); game protocol parsing checks overrun (`src/protocolgame.cpp:463`). The inspected auto-walk parser checks the requested direction count against remaining packet data before skipping it.
- Failed or cancelled accept callbacks now release the pre-registered connection, avoiding a retained `ConnectionManager` entry during service shutdown/retry.
- The launcher release path uses a fixed HTTPS origin, signed ECDSA manifest, SHA-256 package comparison, archive size/count limits, path traversal/collision checks, symlink rejection, and rollback logic (`deploy` C# launcher sources). The launcher and signer compiled successfully with the available .NET SDK.
- Public account/order queries in the inspected PHP sources use PDO prepared statements; registration constrains account/name/password inputs and places account/character creation in a transaction. Private middleware remains out of scope.
- `config.lua` is ignored and not tracked. It was inspected only for safe properties; no values were printed or copied into this report. It uses a non-root DB user and loopback host in this local checkout. This does not establish production configuration.
- A custom limited-pattern scan of 1,675 historical/current text blobs found no matching private-key/token/credential patterns. This is not equivalent to Gitleaks or a provider-side secret scan. A pinned Gitleaks history scan is now configured in CI but has not run in GitHub.

## Validation and limitations

- Python unit tests: 14 passed across load-test parsing, staging safety, and recovery behavior.
- Three local self-tests passed; all seven mutating probes refused execution when staging approval was absent. Bestiary and Quest Log imported without invoking DB/network operations.
- All five legacy deployment scripts refused a phase without the explicit production flag. Both Nginx scripts passed `bash -n` and refused execution without their production-change flag.
- XML: 246/246 files parsed. Python AST parsing: all 27 Python files parsed.
- C# launcher and ReleaseSigner: `dotnet build --no-restore`, 0 warnings and 0 errors each.
- New CI uses pinned GitHub Actions SHAs, read-only default permissions, separate TSan from ASan/UBSan, and a separate release-hardened mode. CodeQL uses its supported `none` build mode for C++/C#. These workflows have not run because this checkout is local and has no GitHub runner attached. If the repository belongs to a GitHub organization, its owner must add the Gitleaks license secret before the secret-scan job can run; personal repositories do not require it.
- Native C++ build, sanitizer/fuzzer runs, Lua/PHP lint, and deployment-tool validation were unavailable locally: no C++ compiler/CMake, LuaJIT, PHP, cppcheck, ShellCheck, actionlint or Docker daemon. Both Nginx scripts did pass Bash syntax checks through Git for Windows. No production/staging services were reachable or used.
- GitHub Actions/branch settings, server firewall, production DB roles, systemd restart/limits, TLS renewal, private web/payment code, and live client update delivery need verification by an operator with access to those systems.

## Prioritized follow-up

1. Run the new workflows on GitHub; fix build/test issues, and make CI/security checks required in branch protection.
2. Measure unauthenticated connection occupancy and legitimate peaks; then design global/per-IP admission and queue limits.
3. Add controlled scheduler cancellation/memory tests and review dispatcher exception semantics plus process supervision.
4. Design compatible password-hash migration; parameterize SQL incrementally and explicitly set DB charset.
5. Add a parser-focused libFuzzer harness only after a standalone entry point can be isolated, then run ASan/UBSan corpus regressions in CI.
6. Review private web/Pix code, production firewall/service/database configuration, release signing-key custody, GitHub settings, backups and restore procedure.

# Antigas security audit

**Snapshot:** 2026-09-29
**Branch:** `security-hardening`
**Method:** source/configuration review, repository/history secret-pattern scan, static parsing, unit tests, and local .NET builds. No production connection, deployment, destructive probe, or public attack simulation was performed.

**Finding totals:** 0 confirmed P0; 0 confirmed unconditional P1; 1 conditional P1; 3 open P2; 1 open P3. Fixed items are listed separately and are not counted as open findings. These are findings from source review, not a claim that the live server has been penetration-tested.

## Inventory and architecture map

The current tracked repository contains 1,723 files: 84 C++ sources, 88 C++ headers, one C source, 750 Lua scripts, 246 XML files, 337 NPC files, 39 `.ndb` data files, 35 JSON files, 3 SQL files, 34 Python files, 3 Shell scripts, 7 PHP files (including a PHP safety regression), 9 C# sources and 3 C# projects, CMake files, and client/server data assets. No Makefile, Dockerfile, submodule, or GitHub Actions workflow existed at the start of this audit. `config.lua` is intentionally ignored.

| Build/CI/dependencies | CMake server build and C# projects; no lockfile or existing CI. | High for regressions and unreviewed dependency drift. | Added local workflows for release/hardened/ASan+UBSan/TSan builds, C++/C# CodeQL, Lua/Python checks, Gitleaks and Dependabot; GitHub execution/settings remain unverified. |

The server build is documented in `README.md`: Linux, CMake and system packages, then `cmake -S . -B build` and `cmake --build build`. The repository does not contain the production systemd unit or an authoritative startup script, so actual service user, restart policy, limits, ports and shutdown ordering cannot be confirmed from this checkout.

## Positive controls observed

- Packet length is bounded before body reads (`src/connection.cpp:157`); game protocol parsing checks the declared cursor boundary (`src/protocolgame.cpp:469`). The inspected auto-walk parser checks the requested direction count against remaining packet data before skipping it.
- NetworkMessage now rejects negative/out-of-range cursor advances and guards reverse reads. The only tracked reverse-read caller is auto-walk, which also validates its direction count before seeking.
- OTCv8 new-walking parsing now checks the inner packet length and refuses to dispatch an empty direction list before its callback can inspect the first step.
- Message-driven game tasks are now gated on the parser cursor remaining inside the declared packet and physical buffer; login and manual dispatcher paths use the same validity check.
- Failed or cancelled accept callbacks now release the pre-registered connection, avoiding a retained `ConnectionManager` entry during service shutdown/retry.
- The launcher release path uses a fixed HTTPS origin, signed ECDSA manifest, SHA-256 package comparison, archive size/count limits, path traversal/collision checks, symlink rejection, and rollback logic (`deploy` C# launcher sources). The launcher and signer compiled successfully with the available .NET SDK.
- Authenticated coin-order pages and Pix QR responses explicitly send `private, no-store` cache directives; this protects payment payloads even though the shared PHP security middleware is outside the checkout.
- Public account/order queries in the inspected PHP sources use PDO prepared statements; registration constrains account/name/password inputs and places account/character creation in a transaction. Private middleware remains out of scope.
- `config.lua` is ignored and not tracked. It was inspected only for safe properties; no values were printed or copied into this report. It uses a non-root DB user and loopback host in this local checkout. This does not establish production configuration.
- A custom limited-pattern scan of 1,675 historical/current text blobs found no matching private-key/token/credential patterns. Gitleaks 8.30.1 also scanned the Git history locally (archive depth 2) and reported zero findings. Neither local scan checks provider-side secrets or proves that secrets were never exposed outside this repository.
- A targeted scan found 12 `addEvent` call sites across the tracked Lua scripts. Review of their timer arguments found no direct `Player`/`Creature`/`Item` userdata passed to callbacks; the identity-bearing cases use numeric IDs, while the other reviewed values are primitive or Lua data tables. `luaAddEvent` only normalizes recognized userdata at the top level, so nested-table safety still depends on each call site. This was a source review, not a LuaJIT runtime lifecycle test.
- `Container::queryAdd` walks ancestors to reject insertion cycles but has no nesting-depth ceiling. The Market's former recursive backpack walk therefore accepted a client-influenced structure whose recursion depth was not bounded. It now traverses iteratively and stops after 10,000 nodes; this bounds Market scan work, not nesting or traversal in other engine subsystems.
- The status protocol previously retained each remote source IP indefinitely in process-global state despite a configured five-second duplicate-query window. The local IP limiter now expires entries using a steady clock; the status port's production exposure still needs firewall verification.
- data/globalevents/lib/lamp_states.lua is persisted bare table data. The runtime loader now validates it with a data-only parser; the CI/local syntax check temporarily prefixes return to compile the table expression without executing it.
